## 一、项目概述

### 1.1 产品定位

基于 Web 的 PWA 应用（GitHub Pages 托管），核心功能为：**日期时间 + 五星评分 + 文字备注** 的简单记录工具。

### 1.2 核心原则

* 极简记录：每次记录为一条独立数据

* 数据安全：本地存储 + 自动备份 + 可选 GitHub 加密同步

* 智能导入：支持多种格式的纯文本导入

* 离线可用：PWA Service Worker 缓存，无网络也可使用

### 1.3 目标平台

* Web 浏览器（Chrome / Safari 等），iOS / Android / 桌面均可访问

* PWA：可安装到主屏、全屏运行，移动端优先（响应式适配）

* 部署：GitHub Pages 静态托管（HTTPS）

## 二、需求汇总（基于50+问题调研 + 逐点 brainstorming 确认）

### 2.1 数据模型

#### 记录（Record）结构

```json
{
  "id": 1716860400000,
  "date": "2024-05-28",
  "time": "22:30",
  "rating": 4,
  "note": "备注内容",
  "tags": ["标签1", "标签2"],
  "createdAt": 1716860400000,
  "updatedAt": 1716860400000
}
```

| 字段      | 类型           | 必填 | 说明                  |
| --------- | -------------- | ---- | --------------------- |
| id        | number         | 是   | 时间戳ID              |
| date      | string         | 是   | 日期，格式 YYYY-MM-DD |
| time      | string \| null | 否   | 可选时间，格式 HH:mm；表单中可清除 |
| rating    | number \| null | 否   | 1-5星评分，无默认值；表单中可清除 |
| note      | string         | 否   | 文字备注，最多500字   |
| tags      | string\[]      | 否   | 标签数组，无数量限制  |
| createdAt | number         | 是   | 创建时间戳            |
| updatedAt | number         | 是   | 修改时间戳            |

> **时段推断**：统计页「时段分布」不新增字段，由 `time` 推断：
> 早 = 05:00-11:59、午 = 12:00-16:59、晚 = 17:00-次日04:59；
> `time` 为 null 的记录归入「未记录时段」，不计入任何段。

#### 数据文件结构

```json
{
  "version": "0.1.0",
  "records": [...]
}
```

* 存储于浏览器 IndexedDB（主存储），单 key 保存完整数据结构

* 包含版本号，方便未来数据迁移

* 每条记录的标签内嵌在记录中，同时维护全局标签列表

#### 全局标签列表

```json
{
  "tags": [
    { "name": "标签名", "color": "#FF5733", "createdAt": 1716860400000 }
  ]
}
```

* 与记录同存于 IndexedDB 的同一数据对象中

* 标签支持用户选择颜色；**新建标签时从默认色板自动分配颜色**（表单内新建不需要手动选色）

* 标签按创建时间排序

* 删除标签时全局删除（需二次确认），同步更新所有记录

* 重命名标签时同步更新所有记录

### 2.2 UI设计

#### 整体架构

* **3个Tab页**：记录页 / 统计页 / 设置页

* Tab栏样式：文字 + SVG图标

* Tab切换：滑动动画

#### 主题系统（铅笔手绘风）

* **唯一主题：铅笔手绘风（sketch-style）**，模拟铅笔手绘素描质感

  * 风格要点：不规则手绘线条（虚线边框）、纸张纹理底色、手写/衬线感字体、素描阴影、涂鸦点缀、温暖手工感

* **明/暗两套配色**，跟随系统明暗模式自动切换（`prefers-color-scheme`）；设置页无主题切换入口

* 主题 token（colors/border/shadow/radius/font/spacing/animation）存储在 `theme_config.json`，Web 侧以 CSS 变量注入

* **风格禁止项**：过大圆角（仅小圆角 rounded-sm 级）、渐变、高饱和霓虹色、玻璃拟态、重阴影、纯白背景、长时平滑动画、过度规则的 hover 效果

* 交互状态：hover 透明度 0.9 / active 0.8 / focus 手绘阴影；动效短促直接（约 0.2s）；支持 `prefers-reduced-motion`

* 点缀色（低饱和铅笔红）用于「今天」标记、评分星星填充、热力图主色等少量强调，其余以铅笔灰阶为主

* 图标为铅笔线条风格 SVG（stroke 线条 + 轻微手绘笔触感，`currentColor`），禁止使用 emoji

* **线条规则（深色虚线 vs 浅色虚线，全站统一）**：

  * **深色虚线（2px dashed，`--line`）**——外层边框/容器级：日历容器、表单弹层边框、记录卡片、日期面板、Toast、月份浮层、空态框等

  * **浅色虚线（1px dashed，`--line-soft`，浅色 #c9c2b2 / 深色 #4a463d）**——内部小边框：输入框、快捷按钮、标签输入、时间框、滚轮分隔、字段分隔线、Tab 栏等

### 2.3 数据存储

#### 存储方案

* **IndexedDB**：记录数据主存储（数据量、读写性能均无压力）

* **localStorage**：应用配置（app_config 键值）

* 无网络依赖：数据全部保存在浏览器本地

#### 备份策略

* 启动时自动备份，**每天最多 1 次**（当日已有备份文件则跳过）

* 备份存储于 IndexedDB 的 backup 表（或独立 key）

* 文件名：`dotoday_backup_` + 时间戳（YYYYMMDD_HHMMSS）

* 保留最近10份备份，自动清理旧备份

* 支持手动触发备份

* 恢复流程：选择备份 → 预览内容 → 确认覆盖

* 支持将备份文件导出下载保存

* **iOS 数据清理对策**（iOS Safari 可能清理长期不使用的 PWA 本地数据）：

  * 启动时检测距上次打开时间，超过 30 天未打开时提示「长时间未使用可能被系统清理，建议导出备份或打开 GitHub 同步」

  * 设置页提供「备份下载导出」入口，方便定期存档

#### GitHub 同步（加密云备份）

* **目的**：将加密后的存档同步到用户自己的 GitHub 仓库，实现跨设备/防丢失备份

* **加密流程**：

  * 用户输入**私钥**（自定义字符串，不在云端明文存储）

  * 私钥经 **PBKDF2**（高迭代次数，约 31 万次）派生 AES-256 密钥，加密时使用随机盐

  * **AES-GCM** 加密完整数据快照（records.json 内容），每次加密生成随机 IV

  * 加密文件内容格式：`{ "version": "0.3.0", "salt": "...", "iv": "...", "data": "..." }`（均为 base64）

  * 不加密的内容仅限文件元信息（时间戳），数据本体密文上传

* **上传**：GitHub REST API `PUT /repos/{owner}/{repo}/contents/{path}`，Token 认证（Authorization: Bearer）

  * 文件路径：`dotoday-sync/dotoday_sync_YYYYMMDD_HHMMSS.json.enc`

  * 每次同步生成新文件，不覆盖旧快照

* **拉取恢复**：`GET /repos/{owner}/{repo}/contents/dotoday-sync` 列出快照 → 选择最新 → 解密（用户输入私钥）→ **自动合并**（无感，单人使用无需手动确认）→ Toast 提示「已同步 N 条记录」

* **合并策略**（单人使用，保持简单无感）：按记录 id 去重，同一 id 取 `updatedAt` 较新者；标签列表取并集。仅在数据版本不兼容等异常时提示手动覆盖

* **Token 要求**：需具备目标仓库 contents 读写权限（建议使用限定单个仓库的最小权限 token）

* 同步为**手动触发**（不做自动定时，降低 token 泄露风险）

* 上传前提示：文件将加密后上传至用户指定仓库

* 私钥仅用于本地加密/解密计算，任何情况下不上传、不落盘到 GitHub

#### 日志

* error.log 追加写入（存储于浏览器本地），超过 **200KB 时轮转**（当前文件改名为 .old，重新开始记录，只保留最近 1 份旧日志）

* 日志分级：info / warn / error

* 设置页「数据管理」提供查看与清空入口

### 2.4 数据导入

#### 导入来源

1. 粘贴纯文本
2. 文件导入（浏览器文件选择器，支持 .txt/.json）

#### 导入格式解析

* 格式不固定，需要智能识别

* 位置相对固定：日期 → 括号内次数 → 备注

* 括号内数字表示次数（全角半角自动转换）

* 备注在最后，到下一个日期模式为止

* 省略年份时根据上下文推断（上一条记录的年份）

* 次数>1时展开为多条独立记录

#### 支持的日期格式

* `2024 1.1` / `2024 1-1`（年+月.日/月-日）

* `2月2日` / `2月2号`（中文月日）

* `2024/1/1` / `2024-01-01`（标准日期格式）

* `1.1`（省略年份）

#### 导入流程

1. 用户粘贴文本或选择文件
2. 智能解析文本，识别日期、次数、备注
3. **预览解析结果**，用户可逐条编辑修改（日期/次数/备注）
4. 遇到无法解析的行：**跳过并在预览中单独列出提示**，用户可手动修改后重新解析（不中止整批导入）
5. 确认后写入数据
6. 导入冲突：合并跳过（相同ID跳过）

> 已移除：手动字段映射（导入格式固定，自动识别即可）。

#### 导入评分

* 导入数据不包含评分信息

* 评分默认为空（null），不是默认3星或5星

### 2.5 数据导出

#### 导出格式

1. **JSON**：完整数据结构
2. **CSV**：UTF-8 BOM编码（Excel兼容）
3. **TXT**：完整格式，每行包含所有字段

#### 导出范围

* 多条件筛选导出（时间范围、评分、标签等）

#### 导出方式

* 浏览器 Blob 下载（自动触发下载文件）

#### 导出隐私

* 可选脱敏（如只保留日期和评分）

#### 文件命名

* 固定前缀 + 时间戳

### 2.6 鲁棒性

| 场景             | 处理方式                       |
| ---------------- | ------------------------------ |
| JSON数据损坏     | 提示用户 + 引导恢复本地备份或从 GitHub 拉取（不自动覆盖） |
| 数据写入失败     | 重试3次后提示用户              |
| 并发写入         | 不需要处理（单用户单设备）     |
| 数据加载         | 全量加载（年数据量几百条，全量渲染无压力） |
| 运行时错误       | 本地错误日志（error.log，200KB轮转） |
| 数据格式升级     | 启动时自动迁移（预留迁移接口） |
| 配置文件不存在   | 自动生成默认配置文件           |
| 浏览器离线       | 已缓存资源正常使用，数据读写不依赖网络 |
| GitHub 同步失败  | 提示错误原因，不阻塞本地使用，记录日志 |

## 三、技术选型

### 3.1 前端框架

* **原生 ES6（无框架、无外部依赖）**，使用原生 ES Modules 组织代码

* 理由：零构建、零依赖，直接静态部署 GitHub Pages；体积小、加载快、完全离线可用

### 3.2 CSS方案

* **手写 CSS + CSS 变量**（主题 token 驱动）

* 铅笔手绘风主题明/暗两套变量，通过 `prefers-color-scheme` 跟随系统

* 移动端优先的响应式布局（flex/grid）

### 3.3 图表库

* **手写 SVG 图表**（柱状图、折线图、环形图、热力图、星期/时段分布）

* 无第三方依赖，渲染快、体积小

### 3.4 模块化

* 原生 ES Modules（`import` / `export`）

* **纯逻辑模块（日期工具/导入解析/统计计算）与 DOM、浏览器存储完全解耦**，可在 node 下直接运行测试

* 依赖浏览器 API 的模块（数据层/日志/导出/同步等）集中管理调用点

### 3.5 存储

* **IndexedDB**：记录数据、备份（异步、容量大）

* **localStorage**：应用配置（同步、轻量）

### 3.6 加密与 GitHub 同步

* **Web Crypto API**：`crypto.subtle` 实现 AES-GCM 加密与 PBKDF2 密钥派生（浏览器原生，无外部库）

* **GitHub REST API**：contents API 上传/拉取加密快照（fetch 调用）

### 3.7 PWA

* **manifest.json**：应用名称、图标、主题色、独立窗口模式

* **Service Worker（sw.js）**：静态资源离线缓存，cache-first 策略；版本更新时清理旧缓存

### 3.8 部署（GitHub Pages）

* 项目推送到 GitHub 仓库，GitHub Pages 静态托管（HTTPS）

* 构建产物即项目根目录（纯静态文件，无构建步骤）

* 用户将存档同步至**同一 GitHub 账户下的任意指定仓库**（私有仓库为佳）

* **本地预览固定端口：8642**（`python -m http.server 8642 --bind 0.0.0.0`），用于 Tailscale 远程预览；后续开发调试一律沿用该端口，不再变更

### 7.3 PWA 与离线策略

* `manifest.json`：name = DoToday / short_name = DoToday / icons（192、512）/ start_url / display: standalone / theme_color

* Service Worker cache-first：首次访问后全部资源离线可用

* 版本更新：`CACHE_VERSION` 递增 → activate 时删除旧缓存 → 下次打开自动获取新版本

* 注册失败不影响应用使用（渐进增强）

### 7.4 GitHub 同步安全设计

* **加密在前，上传在后**：任何上传数据均为 AES-GCM 密文，服务端（GitHub）只见密文

* 密钥派生：用户私钥 + 随机盐 → PBKDF2（31万次迭代）→ AES-256 密钥；盐随文件存储，同一私钥可解密所有快照

* Token 安全：仅存本机 localStorage；建议使用限定单个仓库的最小权限 token；同步为手动触发

* 私钥安全：默认仅内存使用、页面关闭即失；「记住私钥」为可选项（明文存本机，明示风险）；不随数据上传；提示用户妥善保管（丢失无法解密）

* 数据恢复链路：拉取密文 → 输入私钥 → 解密 → 自动合并（按 id 去重、较新 updatedAt 为准）→ 提示合并结果；版本不兼容时提示手动覆盖

## 九、风险与注意事项

### 9.1 技术风险

| 风险               | 影响           | 缓解措施                       |
| ------------------ | -------------- | ------------------------------ |
| 浏览器存储容量     | IndexedDB 无实际容量瓶颈 | 全量加载 + 懒渲染；localStorage 仅存轻量配置 |
| 浏览器兼容性       | 旧浏览器不支持新API | 锁定目标浏览器（iOS 15+ / 近两年 Chrome）；Web Crypto 为广泛支持的标准 |
| Service Worker 缓存更新 | 用户停留旧版本 | CACHE_VERSION 版本控制 + activate 清理旧缓存 |
| iOS 清理 PWA 本地数据   | 长期不用后数据被系统清理 | 30天未打开提示 + 备份导出入口 + GitHub 加密同步兜底 |
| GitHub API 限流    | 同步失败       | 手动同步频率低，天然规避；失败提示 + 日志 |

### 9.2 数据安全

* 数据仅存本机浏览器（IndexedDB），GitHub 上仅存 AES-GCM 密文快照

* 加密密钥由用户私钥派生，私钥不上传；**私钥丢失则密文无法解密**，需提示用户妥善保管

* GitHub Token 仅存本机，建议使用最小权限（限定单仓库）token；同步为手动触发，降低泄露风险

* 应用不涉及其他敏感凭据存储（无 cookie/密码）

### 9.3 性能考量

* 数据量预估：100-500条/年，全量加载 + 懒渲染

* 首次加载：静态资源缓存后秒开；离线可全功能使用

* 图表渲染时间：手写SVG，约0.2-0.5秒

* 加密同步：AES-GCM + PBKDF2 在移动端约 1-3 秒，可接受

* 吸顶目标：默认最新一条记录；点击日历某日期 → 该日第一条记录成为吸顶目标（sticky 切换）+ 滚动到位；回顶恢复默认最新一条并展开完整月历
* 吸顶位随折叠进度动态下移（单周条淡入占位时吸顶记录被推下）；吸顶卡片纸色描边遮挡穿过内容
* 移除锁定（collapseLocked）与吸附（snapToNewest）逻辑

### 0.3.10（2026-08-11）— 折叠锁定与吸附

**修改**：
* 折叠状态机增加**锁定**：滚动驱动折叠完成（progress≥0.99）后锁定，progress 不再随滚动回退（吸附后 scrollY 低于折叠阈值也保持折叠）；点击定位（force-collapse）同步锁定，防止定位滚动中 progress 回退导致偏移
* **折叠完成吸附**：折叠锁定时若最新记录被顶部区（标题+单周条）遮挡，平滑滚动吸附到最新记录紧贴单周条下方（数据不足/本就可见不吸附）
* **解锁**：滚动回顶部（scrollY≤1）解锁，恢复滚动驱动展开

### 0.3.9（2026-08-11）— 标签去重与折叠过渡优化

### 0.3.8（2026-08-11）— 点击定位彻底重构

**修改**：

### 0.3.7（2026-08-11）— 标题固定与滚动驱动动画
